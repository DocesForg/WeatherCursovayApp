# DDL базы данных Bura

В проекте нет отдельных SQL-миграций Flyway/Liquibase или файла `schema.sql`: структура базы данных выводится из JPA-сущностей серверного модуля. Для разработки используется PostgreSQL и режим Hibernate `ddl-auto: update`, поэтому Hibernate может создавать и обновлять таблицы автоматически. Для production-профиля включен `ddl-auto: validate`, то есть приложение только проверяет соответствие уже существующей схемы описанию сущностей.

Ниже приведен DDL, эквивалентный текущим JPA-сущностям проекта для PostgreSQL.

```sql
CREATE TABLE user_account (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    email VARCHAR(255) NOT NULL UNIQUE,
    display_name VARCHAR(255) NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    role VARCHAR(255) NOT NULL
);

CREATE TABLE favorite_city (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    account_id BIGINT NOT NULL,
    city_name VARCHAR(255) NOT NULL,
    latitude DOUBLE PRECISION NOT NULL,
    longitude DOUBLE PRECISION NOT NULL
);

CREATE TABLE support_message (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    account_id BIGINT NOT NULL,
    email VARCHAR(255) NOT NULL,
    name VARCHAR(255) NOT NULL,
    forward_to VARCHAR(255) NOT NULL,
    sender VARCHAR(255) NOT NULL,
    message VARCHAR(4000) NOT NULL,
    created_at TIMESTAMP(6) WITH TIME ZONE NOT NULL,
    seen_by_admin BOOLEAN NOT NULL
);

CREATE TABLE radio_signal_test (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    account_id BIGINT NOT NULL,
    city_a VARCHAR(255) NOT NULL,
    city_b VARCHAR(255) NOT NULL,
    distance_km DOUBLE PRECISION NOT NULL,
    path_loss_db DOUBLE PRECISION NOT NULL,
    quality VARCHAR(255) NOT NULL,
    created_at TIMESTAMP(6) WITH TIME ZONE NOT NULL
);
```

## Описание таблиц

### `user_account`

Таблица учетных записей пользователей.

| Поле | Тип | Ограничения | Описание |
| --- | --- | --- | --- |
| `id` | `BIGINT` | `PRIMARY KEY`, identity | Внутренний идентификатор пользователя. |
| `email` | `VARCHAR(255)` | `NOT NULL`, `UNIQUE` | Email пользователя; используется для поиска аккаунта и не должен повторяться. |
| `display_name` | `VARCHAR(255)` | `NOT NULL` | Отображаемое имя пользователя. |
| `password_hash` | `VARCHAR(255)` | `NOT NULL` | Хэш пароля, а не пароль в открытом виде. |
| `role` | `VARCHAR(255)` | `NOT NULL` | Роль пользователя. По умолчанию в сущности устанавливается `USER`. |

### `favorite_city`

Таблица избранных городов пользователя.

| Поле | Тип | Ограничения | Описание |
| --- | --- | --- | --- |
| `id` | `BIGINT` | `PRIMARY KEY`, identity | Идентификатор записи избранного города. |
| `account_id` | `BIGINT` | `NOT NULL` | Идентификатор владельца записи. |
| `city_name` | `VARCHAR(255)` | `NOT NULL` | Название города. |
| `latitude` | `DOUBLE PRECISION` | `NOT NULL` | Широта города. |
| `longitude` | `DOUBLE PRECISION` | `NOT NULL` | Долгота города. |

### `support_message`

Таблица сообщений поддержки и истории диалогов пользователя с администратором/службой поддержки.

| Поле | Тип | Ограничения | Описание |
| --- | --- | --- | --- |
| `id` | `BIGINT` | `PRIMARY KEY`, identity | Идентификатор сообщения. |
| `account_id` | `BIGINT` | `NOT NULL` | Идентификатор пользователя, к которому относится диалог. |
| `email` | `VARCHAR(255)` | `NOT NULL` | Email пользователя для связи. |
| `name` | `VARCHAR(255)` | `NOT NULL` | Имя пользователя в обращении. |
| `forward_to` | `VARCHAR(255)` | `NOT NULL` | Адрес/направление пересылки обращения. |
| `sender` | `VARCHAR(255)` | `NOT NULL` | Отправитель сообщения, например пользователь или администратор. |
| `message` | `VARCHAR(4000)` | `NOT NULL` | Текст сообщения; длина ограничена 4000 символами. |
| `created_at` | `TIMESTAMP(6) WITH TIME ZONE` | `NOT NULL` | Дата и время создания сообщения. |
| `seen_by_admin` | `BOOLEAN` | `NOT NULL` | Признак того, что сообщение уже просмотрено администратором. |

### `radio_signal_test`

Таблица сохраненных расчетов/тестов радиосигнала между двумя городами.

| Поле | Тип | Ограничения | Описание |
| --- | --- | --- | --- |
| `id` | `BIGINT` | `PRIMARY KEY`, identity | Идентификатор результата теста. |
| `account_id` | `BIGINT` | `NOT NULL` | Идентификатор пользователя, выполнившего расчет. |
| `city_a` | `VARCHAR(255)` | `NOT NULL` | Первый город маршрута радиосигнала. |
| `city_b` | `VARCHAR(255)` | `NOT NULL` | Второй город маршрута радиосигнала. |
| `distance_km` | `DOUBLE PRECISION` | `NOT NULL` | Расстояние между городами в километрах. |
| `path_loss_db` | `DOUBLE PRECISION` | `NOT NULL` | Расчетные потери сигнала в децибелах. |
| `quality` | `VARCHAR(255)` | `NOT NULL` | Текстовая оценка качества радиосигнала. |
| `created_at` | `TIMESTAMP(6) WITH TIME ZONE` | `NOT NULL` | Дата и время сохранения результата. |

## Связи и ограничения

Явные внешние ключи между таблицами в сущностях не описаны: поля `account_id` хранят идентификатор пользователя как обычное числовое поле. Поэтому на уровне DDL Hibernate создает только первичные ключи, `NOT NULL`-ограничения и уникальность `user_account.email`.

Индексы, кроме первичных ключей и уникального ограничения на email, в сущностях также не заданы. При необходимости ускорить выборки по `account_id`, `created_at` или `city_name` их можно добавить отдельными миграциями.
