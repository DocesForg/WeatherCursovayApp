# ADR-006: Использовать Open-Meteo как внешний погодный источник

**Статус:** Принято  
**Дата:** 31.05.2026  
**Источник:** раздел «Архитектурные решения» в [`arc42-overview.md`](../arc42-overview.md)

## Контекст

Bura показывает прогноз погоды, графики, метеосводки, выполняет поиск городов и использует погодный snapshot при расчете радиосигнала. Для учебного проекта нужен доступный внешний источник погодных и геокодинговых данных без сложной платной интеграции.

## Решение

Использовать Open-Meteo Forecast API и Open-Meteo Geocoding API как внешний источник погодных данных, геокодинга и текущих погодных snapshots.

## Обоснование

Open-Meteo предоставляет бесплатный API для прогноза, геокодинга и текущих погодных данных. Это позволяет реализовать основные погодные функции и модуль радиотеста без собственной метеорологической инфраструктуры.

## Последствия

### Положительные

- Приложение получает прогноз, hourly/daily параметры и геокодинг городов из единого публичного источника.
- Backend может использовать погодный snapshot для расчета качества радиоканала.
- Не требуется собственная база погодных наблюдений.
- Бесплатный внешний API снижает стоимость учебного проекта.

### Отрицательные / ограничения

- Доступность и формат данных зависят от внешнего сервиса.
- При недоступности Open-Meteo приложение должно использовать кэш или показывать ошибку загрузки.
- Изменение API может потребовать обновления downloader/converter логики и DTO.
