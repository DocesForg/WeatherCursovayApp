# ADR-005: Использовать JWT Bearer auth

**Статус:** Принято  
**Дата:** 31.05.2026  
**Источник:** раздел «Архитектурные решения» в [`arc42-overview.md`](../arc42-overview.md)

## Контекст

Bura поддерживает регистрацию, вход, пользовательские аккаунты и роль администратора. Android-клиент должен обращаться к backend API без server-side session storage, а backend должен проверять доступ пользователя к собственным данным и закрывать административные endpoints.

## Решение

Использовать JWT Bearer аутентификацию. После входа backend возвращает JWT, Android сохраняет auth-session локально и передает токен в заголовке `Authorization: Bearer ...` при обращении к защищенным endpoints.

## Обоснование

JWT Bearer auth обеспечивает stateless backend и простую интеграцию с мобильным клиентом. Spring Security проверяет токен, роли и доступ к данным аккаунта.

## Последствия

### Положительные

- Backend не хранит server-side пользовательские сессии.
- Android-клиент может единообразно авторизовывать REST-запросы через Retrofit/OkHttp.
- Роли USER/ADMIN и проверки `accountId` централизуются в security layer.
- При HTTP 401 клиент может очистить локальную session state.

### Отрицательные / ограничения

- Нужно защищать JWT secret и корректно настраивать срок действия токена.
- При компрометации токена злоумышленник получает доступ до истечения срока действия.
- Клиент должен безопасно хранить и очищать локальную auth-session.
