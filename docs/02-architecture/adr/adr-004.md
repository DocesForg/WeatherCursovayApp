# ADR-004: Использовать PostgreSQL и Spring Data JPA

**Статус:** Принято  
**Дата:** 31.05.2026  
**Источник:** раздел «Архитектурные решения» в [`arc42-overview.md`](../arc42-overview.md)

## Контекст

Backend Bura хранит пользовательские аккаунты, роли, избранные города, обращения в поддержку и историю расчетов радиосигнала. Данные должны быть надежно сохранены между запусками, доступны через repository layer и удобны для запросов статистики.

## Решение

Использовать PostgreSQL как основную базу данных backend и Spring Data JPA как слой доступа к данным.

## Обоснование

PostgreSQL обеспечивает надежное хранение пользовательских данных, а Spring Data JPA дает простой repository layer с декларативными методами поиска, сохранения и удаления сущностей.

## Последствия

### Положительные

- Пользовательские данные сохраняются в промышленной реляционной СУБД.
- JPA entities напрямую отражают таблицы backend-домена.
- Repository interfaces сокращают объем ручного SQL-кода.
- PostgreSQL удобно запускать локально через Docker Compose.

### Отрицательные / ограничения

- Требуется управлять схемой базы данных и настройками подключения.
- Нужно следить за корректностью JPA-связей, транзакций и миграций.
- Для production-сценариев потребуется более строгая миграционная стратегия.
