# ADR-001: Использовать PCMEF как архитектурную декомпозицию

**Статус:** Принято  
**Дата:** 31.05.2026  
**Источник:** раздел «Архитектурные решения» в [`arc42-overview.md`](../arc42-overview.md)

## Контекст

Bura объединяет Android-приложение и Spring Boot backend. В системе есть UI-экраны, навигация, состояния ViewModel, бизнес-сценарии, доменные модели, REST-интерфейсы, локальное хранилище Room, PostgreSQL и внешние API Open-Meteo.

Без явной декомпозиции логика экранов, сетевых вызовов, кэширования, авторизации и хранения данных может смешиваться, что усложнит поддержку, тестирование и расширение учебного проекта.

## Решение

Использовать PCMEF (Presentation-Control-Mediator-Entity-Foundation) как основную архитектурную декомпозицию проекта.

Слои распределяются так:

| Слой | Назначение в Bura |
|------|-------------------|
| Presentation | Compose UI, destinations, admin panel, Swagger UI. |
| Control | ViewModel, REST controllers, security filter, обработка входных действий. |
| Mediator | Repositories/use-cases на Android, services и расчетная логика на backend. |
| Entity | Доменные модели, DTO, Room entities, JPA entities. |
| Foundation | Retrofit, Room DAO, SharedPreferences, Spring Data JPA, PostgreSQL, внешние HTTP API. |

## Обоснование

PCMEF требуется для разделения UI, управления, бизнес-логики, сущностей и инфраструктуры. Такая схема хорошо соответствует смешанной mobile + backend архитектуре проекта и позволяет описывать оба приложения единым архитектурным языком.

## Последствия

### Положительные

- Упрощается навигация по модулям и документации.
- UI не должен напрямую обращаться к базе данных или внешним сервисам.
- Backend controllers остаются HTTP-границей, а бизнес-операции выносятся в сервисы.
- Проще расширять проект новыми экранами, endpoints и хранилищами.

### Отрицательные / ограничения

- Нужно поддерживать дисциплину зависимостей между слоями.
- Для небольших сценариев появляется дополнительная структура и документация.
- При расширении проекта необходимо обновлять PCMEF-описание и интерфейсные документы.
