# Use Case диаграмма Bura

Файл `/docs/01-requirements/code-diagram/use-case.md` содержит Use Case диаграмму для проекта Bura — мобильного приложения прогноза погоды с собственным backend-сервером. Диаграмма показывает, какие пользовательские и административные сценарии поддерживает система, а также какие внешние сервисы участвуют в их выполнении.

<img src="/docs/01-requirements/images/use-case.png" alt="use case диаграмма">

## Участники диаграммы

- **Гость** — неавторизованный пользователь, который может зарегистрироваться или войти в приложение.
- **Пользователь** — авторизованный владелец аккаунта, которому доступны основные функции приложения: просмотр погоды, работа с избранным, профиль, поддержка и радиотесты.
- **Администратор** — расширенная роль пользователя, которая дополнительно управляет аккаунтами, ролями, dashboard и обращениями в поддержку.
- **Open-Meteo API** — внешний сервис, используемый для поиска городов и получения погодного прогноза.
- **Bura Backend** — серверная часть приложения, отвечающая за аккаунты, JWT-авторизацию, избранные города, поддержку, статистику и историю радиотестов.

## Основные сценарии

Диаграмма разделяет систему на две области:

1. **Мобильное приложение Bura** — включает сценарии регистрации, входа, выбора города, просмотра сводки погоды, просмотра графиков, настройки темы и единиц измерения, управления профилем, избранными городами, обращениями в поддержку и радиотестами.
2. **Сервер Bura** — включает сценарии выдачи JWT, хранения данных аккаунта, избранного, обращений поддержки, радиотестов, расчета статистики и административного управления.

Связи `<<include>>` показывают обязательные вложенные действия. Например, просмотр прогноза включает получение данных прогноза, а выбор города включает поиск города. Связи `<<extend>>` отражают дополнительные или условные сценарии, например работу с кэшем и офлайн-данными при просмотре погоды.

## Назначение диаграммы

Диаграмма нужна для быстрого понимания границ системы и распределения ответственности между мобильным приложением, backend-сервером, внешним погодным API и ролями пользователей. Ее можно использовать в проектной документации, пояснительной записке или при обсуждении функциональных требований.

# Domain Model (диаграмма классов)
Файл `/docs/01-requirements/code-diagram/domain.md` содержит Domain диаграмму

Модель предметной области описывает ключевые сущности системы и взаимосвязи между ними. Центральными элементами домена являются пользовательский аккаунт, географическое местоположение, прогноз погоды и сообщения поддержки. Каждая сущность имеет свои атрибуты и методы, определяющие её поведение в системе.

<img src="/docs/01-requirements/images/domain.png" alt="Domain диаграмма">

Класс UserAccount представляет учётную запись пользователя и содержит основные данные для аутентификации и авторизации. Сущность связана с классами FavoriteCity и SupportMessage отношением один-ко-многим, поскольку один пользователь может иметь несколько избранных городов и участвовать в нескольких диалогах поддержки.

Класс Place описывает географическое местоположение с полной информацией о названии, административных делениях и координатах. Данная сущность используется как основа для создания объектов SavedPlace, которые представляют избранные города с дополнительными данными о текущих погодных условиях.

Класс WeatherForecast агрегирует различные типы метеорологических данных, организованных в периоды времени. Почасовые и ежедневные данные представлены отдельными классами для обеспечения чёткой структуры и удобства обработки.

### Описание сущностей и атрибутов

**UserAccount (Пользовательский аккаунт)**

Сущность представляет учётную запись пользователя в системе. Идентификатор id является автоинкрементируемым первичным ключом базы данных. Поле email хранит уникальный адрес электронной почты, используемый для входа в систему, и не может быть пустым. DisplayName содержит отображаемое имя пользователя, которое может быть изменено через настройки профиля. PasswordHash хранит криптографический хэш пароля, созданный с использованием алгоритма BCrypt для безопасного хранения учётных данных. Поле role определяет роль пользователя в системе и принимает значения USER или ADMIN, определяя уровень доступа к функциям приложения.

**FavoriteCity (Избранный город)**

Сущность представляет сохранённое пользователем географическое местоположение. Идентификатор id служит первичным ключом. AccountId является внешним ключом, ссылающимся на таблицу user_account и обеспечивающим связь с владельцем. CityName хранит название города в том виде, в котором оно было получено от геокодирующего сервиса. Latitude и longitude представляют географические координаты в десятичном формате WGS84, необходимые для запросов к погодному API.

**SupportMessage (Сообщение поддержки)**

Сущность моделирует отдельное сообщение в диалоге между пользователем и службой поддержки. Id является первичным ключом. AccountId связывает сообщение с аккаунтом отправителя. Email, name хранят контактные данные пользователя на момент отправки сообщения. ForwardTo содержит адрес электронной почты службы поддержки, куда пересылаются уведомления. Sender указывает тип отправителя (USER или ADMIN) для правильного отображения в интерфейсе. Message содержит текст сообщения ограниченной длины. CreatedAt фиксирует временную метку создания сообщения. SeenByAdmin является булевым флагом, указывающим, было ли сообщение прочитано администратором.

**Place (Местоположение)**

Сущность описывает географическое местоположение с полной информацией об адресе. Name содержит основное название населённого пункта. Поля admin1-admin4 хранят названия административных единиц разных уровней (область, район и т.д.). CountryCode представляет двухбуквенный код страны по стандарту ISO 3166-1. CountryName содержит полное название страны. Location является композитным атрибутом, содержащим временную зону и координаты местоположения.

**WeatherForecast (Прогноз погоды)**

Класс агрегирует все типы метеорологических данных, полученных от внешнего API. Температура, ощущаемая температура, осадки, ветер, давление, влажность, видимость, УФ-индекс, солнечная активность и условия облачности представлены отдельными периодами данных. Каждый период содержит почасовые значения для детального почасового прогноза и ежедневные агрегированные значения для сводки по дням.
